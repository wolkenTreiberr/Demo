## ЧТО ТАКОЕ DATA CLASS?
---
Data class — класс, предназначенный для хранения данных. Компилятор автоматически генерирует: equals(), hashCode(), toString(), copy(), componentN() (для деструктуризации).

```kotlin
data class User(val name: String, val age: Int)

val user = User("Иван", 25)
println(user)                    // User(name=Иван, age=25) — автогенерированный toString()
println(user == User("Иван", 25)) // true — сравнение по содержимому (equals)
```

Требования к data class:
- Primary constructor должен иметь хотя бы один параметр
- Все параметры primary constructor — val или var
- Не может быть abstract, open, sealed или inner

Автогенерация работает ТОЛЬКО по свойствам из primary constructor. Свойства в теле класса НЕ участвуют:

```kotlin
data class User(val name: String) {
    var loginCount: Int = 0 // НЕ участвует в equals, hashCode, toString, copy
}

val u1 = User("Иван")
val u2 = User("Иван")
u1.loginCount = 10
println(u1 == u2) // true — loginCount не учитывается!
```

copy() — создание копии с изменением отдельных свойств:

```kotlin
data class User(val name: String, val age: Int)

val original = User("Иван", 25)
val copy = original.copy(age = 26)
println(copy) // User(name=Иван, age=26)
```

copy() делает поверхностную копию (shallow copy). Если свойство — мутабельный объект (список, map), копия и оригинал будут ссылаться на один и тот же объект.

Деструктуризация через componentN():

```kotlin
val user = User("Иван", 25)
val (name, age) = user  // name = "Иван", age = 25

// удобно в циклах
val users = listOf(User("Иван", 25), User("Анна", 30))
for ((name, age) in users) {
    println("$name: $age")
}
```

componentN() генерируется по порядку свойств в primary constructor: component1() = первое свойство, component2() = второе и т.д.

Когда использовать data class:
- DTO (Data Transfer Objects), модели API-ответов
- Состояния (state) в BLoC/ViewModel
- Ключи для Map (корректный equals/hashCode)
- Любые объекты-контейнеры данных
!!!
## ЧТО ТАКОЕ ENUM CLASS?
---
Enum class — класс для определения фиксированного набора констант. Каждая константа — экземпляр enum класса.

```kotlin
enum class Direction {
    NORTH, SOUTH, EAST, WEST
}

val dir = Direction.NORTH
println(dir)       // NORTH
println(dir.name)  // "NORTH" — имя константы как строка
println(dir.ordinal) // 0 — порядковый номер (с нуля)
```

Enum с свойствами — каждая константа может хранить данные:

```kotlin
enum class Color(val rgb: String, val hex: Int) {
    RED("Red", 0xFF0000),
    GREEN("Green", 0x00FF00),
    BLUE("Blue", 0x0000FF);  // ТОЧКА С ЗАПЯТОЙ обязательна перед методами/свойствами
}

println(Color.RED.rgb) // Red
println(Color.RED.hex) // 16711680
```

Enum с абстрактными методами — каждая константа реализует свою версию:

```kotlin
enum class Operation {
    ADD {
        override fun apply(a: Double, b: Double) = a + b
    },
    SUBTRACT {
        override fun apply(a: Double, b: Double) = a - b
    },
    MULTIPLY {
        override fun apply(a: Double, b: Double) = a * b
    };

    abstract fun apply(a: Double, b: Double): Double
}

println(Operation.ADD.apply(3.0, 2.0))      // 5.0
println(Operation.MULTIPLY.apply(3.0, 2.0)) // 6.0
```

Enum может реализовывать интерфейсы:

```kotlin
interface Printable {
    fun prettyPrint(): String
}

enum class Priority : Printable {
    LOW {
        override fun prettyPrint() = "Низкий"
    },
    MEDIUM {
        override fun prettyPrint() = "Средний"
    },
    HIGH {
        override fun prettyPrint() = "Высокий"
    };
}
```

Получение констант:

```kotlin
// entries (Kotlin 1.9+) — рекомендуемый способ, возвращает List
val allDirections: List<Direction> = Direction.entries
allDirections.forEach { println(it) }

// values() — старый способ, возвращает Array (менее эффективен)
val array: Array<Direction> = Direction.values()

// valueOf() — по имени строки, бросает IllegalArgumentException если не найден
val north = Direction.valueOf("NORTH") // Direction.NORTH
// Direction.valueOf("INVALID") — IllegalArgumentException
```

Enum и when — компилятор проверяет что все варианты покрыты (exhaustive):

```kotlin
fun describe(dir: Direction): String = when (dir) {
    Direction.NORTH -> "Север"
    Direction.SOUTH -> "Юг"
    Direction.EAST -> "Восток"
    Direction.WEST -> "Запад"
    // else не нужен — компилятор знает что все варианты покрыты
}
```

Когда использовать enum:
- Фиксированный набор вариантов, известный на этапе компиляции
- Статусы (PENDING, ACTIVE, DONE), роли (ADMIN, USER), направления
- Замена магических строк и чисел
!!!
## ЧТО ТАКОЕ SEALED CLASS И SEALED INTERFACE?
---
Sealed class/interface — ограниченная иерархия, где все наследники известны на этапе компиляции. Наследники должны быть объявлены в том же пакете (и модуле) что и sealed класс.

Зачем: компилятор знает ВСЕ возможные подтипы и может гарантировать exhaustive when без else.

```kotlin
sealed class Result {
    data class Success(val data: String) : Result()
    data class Error(val message: String, val code: Int) : Result()
    data object Loading : Result()
}

fun handle(result: Result): String = when (result) {
    is Result.Success -> "Данные: ${result.data}"
    is Result.Error -> "Ошибка ${result.code}: ${result.message}"
    Result.Loading -> "Загрузка..."
    // else не нужен — компилятор знает все варианты
}
```

Sealed class vs Enum:
- Enum: каждая константа — единственный экземпляр (singleton). Все константы одного типа
- Sealed class: каждый наследник — отдельный класс со своими свойствами. Success хранит data, Error хранит message и code

Sealed interface — то же самое, но без ограничения на одиночное наследование:

```kotlin
sealed interface Error {
    data class Network(val code: Int) : Error
    data class Validation(val field: String, val reason: String) : Error
    data object Unknown : Error
}

// Класс может реализовать несколько sealed interfaces
sealed interface Loggable
data class NetworkError(val code: Int) : Error, Loggable
```

Ограничения:
- Sealed class не может быть instantiated напрямую (как abstract)
- Все прямые наследники — в том же пакете и модуле
- Наследники могут быть data class, object, обычный class или другой sealed class

Типичное применение:
- Состояния экрана (Loading, Success, Error)
- Результаты операций (Success/Failure)
- Навигационные события
- Действия (Actions) в MVI/Redux-архитектуре

```kotlin
// Реальный пример — состояние UI
sealed class UiState<out T> {
    data object Loading : UiState<Nothing>()
    data class Success<T>(val data: T) : UiState<T>()
    data class Error(val exception: Throwable) : UiState<Nothing>()
}

fun <T> renderState(state: UiState<T>) = when (state) {
    is UiState.Loading -> showSpinner()
    is UiState.Success -> showData(state.data)
    is UiState.Error -> showError(state.exception.message)
}
```

## ЧТО ТАКОЕ OBJECT DECLARATION (SINGLETON)?
---
Object declaration — создание singleton-объекта (единственный экземпляр). Объявляется через ключевое слово object вместо class.

```kotlin
object DatabaseConfig {
    val url = "jdbc:postgresql://localhost:5432/db"
    val maxConnections = 10

    fun connect() {
        println("Подключение к $url")
    }
}

// Использование — без создания экземпляра
DatabaseConfig.connect()
println(DatabaseConfig.maxConnections) // 10
```

Object — это одновременно объявление класса И создание единственного экземпляра. Инициализация — ленивая и потокобезопасная (при первом обращении).

Object может наследовать классы и реализовывать интерфейсы:

```kotlin
interface Logger {
    fun log(message: String)
}

object ConsoleLogger : Logger {
    override fun log(message: String) {
        println("[LOG] $message")
    }
}

// Можно передать как реализацию интерфейса
fun setup(logger: Logger) {
    logger.log("Инициализация")
}

setup(ConsoleLogger)
```

Object НЕ может иметь конструктор (ни primary, ни secondary) — он один и создаётся автоматически.

Когда использовать:
- Singleton-сервисы (логгер, конфигурация, кеш)
- Реализации интерфейсов без состояния
- Замена Java-паттерна Singleton (не нужен boilerplate)
- Константы и утилиты (хотя для утилит часто лучше top-level функции)
!!!
## ЧТО ТАКОЕ COMPANION OBJECT?
---
Companion object — объект, привязанный к классу. Его члены вызываются через имя класса (аналог static в Java, но это полноценный объект).

```kotlin
class User(val name: String) {
    companion object {
        const val MAX_NAME_LENGTH = 50

        fun create(name: String): User {
            require(name.length <= MAX_NAME_LENGTH)
            return User(name)
        }
    }
}

// Вызов через имя класса
val user = User.create("Иван")
println(User.MAX_NAME_LENGTH) // 50
```

Companion object может иметь имя:

```kotlin
class User(val name: String) {
    companion object Factory {
        fun create(name: String) = User(name)
    }
}

val user = User.Factory.create("Иван") // можно через имя
val user2 = User.create("Иван")        // можно без имени — тоже работает
```

Companion object может реализовывать интерфейсы:

```kotlin
interface JsonDeserializer<T> {
    fun fromJson(json: String): T
}

data class Config(val host: String, val port: Int) {
    companion object : JsonDeserializer<Config> {
        override fun fromJson(json: String): Config {
            // парсинг...
            return Config("localhost", 8080)
        }
    }
}

// Передаём companion object как объект
fun <T> load(deserializer: JsonDeserializer<T>, json: String): T {
    return deserializer.fromJson(json)
}

val config = load(Config, "{}")  // Config — ссылка на companion object
```

Важно: companion object — НЕ static. Это реальный объект с инициализацией. Для настоящих compile-time констант используй const val (только примитивы и String).

Один companion object на класс. Если нужно несколько "групп" — используй обычные named objects внутри класса.

Когда использовать:
- Factory methods (альтернативные конструкторы с осмысленными именами)
- Константы, связанные с классом
- Реализация интерфейса на уровне класса (сериализация, десериализация)
!!!
## ЧТО ТАКОЕ DATA OBJECT?
---
Data object (Kotlin 1.9+) — object с автогенерированным toString(). Используется как singleton-элемент в sealed-иерархиях рядом с data class.

Проблема обычного object:

```kotlin
sealed class Result {
    data class Success(val data: String) : Result()
    object Loading : Result()  // обычный object
}

println(Result.Loading) // Result$Loading@3f99bd52 — некрасивый toString()
```

Решение — data object:

```kotlin
sealed class Result {
    data class Success(val data: String) : Result()
    data object Loading : Result()  // data object
}

println(Result.Loading) // Loading — чистый toString()
```

Data object генерирует:
- toString() — имя класса (без хеша)
- equals() и hashCode() — но для singleton это не особо важно (есть только один экземпляр)

Data object НЕ генерирует copy() и componentN() — для singleton они бессмысленны.

Когда использовать: всегда, когда нужен object внутри sealed-иерархии (Loading, EndOfFile, Empty, None). Нет причин использовать обычный object вместо data object в таких случаях.
!!!
## ЧТО ТАКОЕ NESTED И INNER КЛАССЫ?
---
Nested class — класс, объявленный внутри другого класса. По умолчанию НЕ имеет доступа к членам внешнего класса (аналог static nested class в Java).

```kotlin
class Outer(val name: String) {
    class Nested {
        fun greet() = "Привет из Nested"
        // name — НЕ доступен, нет ссылки на Outer
    }
}

val nested = Outer.Nested()  // создаётся БЕЗ экземпляра Outer
println(nested.greet())      // Привет из Nested
```

Inner class — вложенный класс с модификатором inner. ИМЕЕТ доступ к членам внешнего класса через неявную ссылку:

```kotlin
class Outer(val name: String) {
    inner class Inner {
        fun greet() = "Привет от $name"  // доступ к Outer.name
        fun getOuter() = this@Outer      // явная ссылка на Outer
    }
}

val outer = Outer("Kotlin")
val inner = outer.Inner()  // нужен экземпляр Outer
println(inner.greet())     // Привет от Kotlin
```

Ключевые отличия:
- Nested (без inner): не хранит ссылку на Outer, создаётся через Outer.Nested()
- Inner (с inner): хранит ссылку на Outer, создаётся через экземпляр outer.Inner()

Inner class держит ссылку на внешний объект. Это значит:
- Внешний объект не будет собран GC пока жив inner-экземпляр
- Потенциальная утечка памяти, если inner живёт дольше outer

Правило: используй nested (без inner) по умолчанию. Добавляй inner только когда реально нужен доступ к внешнему классу.

Типичное применение nested: группировка связанных классов (Builder, ViewHolder, Adapter).

```kotlin
class RecyclerView {
    class ViewHolder(val view: View)  // nested — не нужна ссылка на RecyclerView

    abstract class Adapter {          // nested — переопределяется извне
        abstract fun onCreateViewHolder(): ViewHolder
    }
}
```

Типичное применение inner: итераторы, обработчики, которым нужен доступ к состоянию внешнего объекта.
!!!
## ЧТО ТАКОЕ ANONYMOUS CLASSES И OBJECT EXPRESSIONS?
---
Object expression — создание анонимного объекта "на месте", без объявления именованного класса. Используется для одноразовых реализаций интерфейсов или абстрактных классов.

```kotlin
interface ClickListener {
    fun onClick(id: String)
}

fun setListener(listener: ClickListener) {
    listener.onClick("btn-1")
}

// Анонимная реализация через object expression
setListener(object : ClickListener {
    override fun onClick(id: String) {
        println("Нажата кнопка: $id")
    }
})
```

Object expression может реализовывать несколько интерфейсов:

```kotlin
interface A { fun a() }
interface B { fun b() }

val obj = object : A, B {
    override fun a() = println("A")
    override fun b() = println("B")
}

obj.a() // A
obj.b() // B
```

Object expression без суперкласса — ad-hoc объект с произвольными свойствами:

```kotlin
val point = object {
    val x = 10
    val y = 20
    override fun toString() = "($x, $y)"
}

println(point.x)  // 10
println(point)    // (10, 20)
```

Важно: тип ad-hoc объекта доступен только в локальном контексте. Если вернуть его из функции или присвоить public-свойству — тип будет Any:

```kotlin
class Demo {
    // private — тип анонимного объекта виден
    private val point = object { val x = 10 }

    // public — тип стирается до Any
    val publicPoint = object { val x = 10 }

    fun test() {
        println(point.x)       // OK — private, тип виден
        // println(publicPoint.x) // ОШИБКА — public, тип = Any
    }
}
```

Object expression захватывает переменные из окружающего контекста (замыкание), включая var:

```kotlin
var clickCount = 0
setListener(object : ClickListener {
    override fun onClick(id: String) {
        clickCount++ // модификация захваченной переменной
    }
})
```

Когда использовать:
- Одноразовая реализация интерфейса (callback, listener)
- Тестовые заглушки (в простых случаях)
- Когда лямбда не подходит (интерфейс с несколькими методами)

Когда НЕ использовать:
- Если интерфейс с одним методом — лучше лямбда (SAM-conversion)
- Если реализация нужна в нескольких местах — создай именованный класс
!!!
## СРАВНЕНИЕ ВСЕХ ТИПОВ КЛАССОВ
---
Data class:
- Зачем: хранение данных
- Что даёт: equals, hashCode, toString, copy, componentN
- Пример: модели API, состояния UI, DTO

Enum class:
- Зачем: фиксированный набор констант
- Что даёт: name, ordinal, entries, valueOf, exhaustive when
- Пример: статусы, роли, направления, типы операций

Sealed class/interface:
- Зачем: ограниченная иерархия с разными типами данных
- Что даёт: exhaustive when, наследники с разными свойствами
- Пример: Result (Success/Error/Loading), события, действия

Object:
- Зачем: singleton
- Что даёт: единственный экземпляр, ленивая инициализация
- Пример: конфигурация, логгер, DI-контейнер

Companion object:
- Зачем: "статические" члены класса
- Что даёт: вызов через имя класса, может реализовать интерфейсы
- Пример: factory methods, константы, десериализация

Data object:
- Зачем: singleton с чистым toString()
- Что даёт: toString() без хеша
- Пример: элементы sealed-иерархии без данных (Loading, Empty)

Nested class:
- Зачем: группировка связанных классов
- Что даёт: логическая организация без ссылки на outer
- Пример: Builder, ViewHolder, вложенные типы

Inner class:
- Зачем: вложенный класс с доступом к outer
- Что даёт: ссылка на внешний объект
- Пример: итераторы, обработчики с доступом к состоянию

Object expression:
- Зачем: одноразовая реализация
- Что даёт: анонимный объект на месте
- Пример: callbacks, listeners, тестовые заглушки
