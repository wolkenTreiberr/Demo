## ЧТО ТАКОЕ УПРАВЛЯЮЩИЕ КОНСТРУКЦИИ В KOTLIN?
---
Управляющие конструкции (control flow) — конструкции языка, которые определяют порядок выполнения кода в зависимости от условий.

Условные конструкции в Kotlin:
- if / else — классическое ветвление
- when — замена switch из Java/C

Ключевая особенность Kotlin: и if, и when являются выражениями (expression), а не только инструкциями (statement). Это значит что они возвращают значение и могут использоваться в присваивании.

```kotlin
// if как выражение
val max = if (a > b) a else b

// when как выражение
val label = when (role) {
    "Admin" -> "Полный доступ"
    else -> "Ограниченный доступ"
}
```

Разница между expression и statement:
- Statement — выполняет действие, не возвращает значение (как if в Java)
- Expression — выполняет действие И возвращает значение (как if/when в Kotlin)

Оба конструкции могут использоваться и как statement (без присваивания), и как expression (с присваиванием результата). Когда if используется как expression — ветка else обязательна (компилятор должен знать что вернуть в любом случае).
!!!
## ЧТО ТАКОЕ IF-ELSE И В ЧЁМ ОСОБЕННОСТЬ В KOTLIN?
---
if/else — условная конструкция, выполняющая код в зависимости от булевого условия.

Главная особенность: в Kotlin if — это expression (выражение), а не statement. Он возвращает значение — результат последнего выражения в блоке.

Как statement (без возврата значения):

```kotlin
if (score >= 90) {
    println("Отлично")
} else {
    println("Попробуй ещё")
}
```

Как expression (с возвратом значения):

```kotlin
val result = if (score >= 90) "Отлично" else "Попробуй ещё"
```

Многострочные блоки — последнее выражение в блоке становится результатом:

```kotlin
val max = if (a > b) {
    println("Выбран a")
    a
} else {
    println("Выбран b")
    b
}
```

Цепочки else if:

```kotlin
val grade = if (score >= 90) "A"
    else if (score >= 80) "B"
    else if (score >= 70) "C"
    else "F"
```

Правила:
- Как expression — ветка else обязательна
- Как statement — else не обязателен
- В блоке с несколькими выражениями — возвращается последнее
!!!
## ПОЧЕМУ В KOTLIN НЕТ ТЕРНАРНОГО ОПЕРАТОРА?
---
В Kotlin нет тернарного оператора (condition ? then : else) потому что if сам является выражением и возвращает значение. Отдельный синтаксис не нужен.

Сравнение:

```kotlin
// Java
String result = (score >= 90) ? "A" : "F";

// Kotlin — if-expression делает то же самое
val result = if (score >= 90) "A" else "F"
```

if-expression читается понятнее тернарного оператора, особенно при вложенных условиях.
!!!
## ЧТО ТАКОЕ WHEN И КАКИЕ ВИДЫ БЫВАЮТ?
---
when — условная конструкция, которая проверяет значение по нескольким веткам. Замена switch из Java/C с расширенными возможностями.

Два вида по наличию аргумента:

1. when с аргументом — проверяет значение аргумента по веткам:

```kotlin
when (status) {
    "OK" -> println("Успех")
    "ERROR" -> println("Ошибка")
    else -> println("Неизвестно")
}
```

2. when без аргумента — каждая ветка содержит булево выражение (замена цепочек if-else if):

```kotlin
when {
    score >= 90 -> "A"
    score >= 80 -> "B"
    else -> "F"
}
```

Два вида по использованию:

- Как expression — возвращает значение, присваивается переменной
- Как statement — выполняет действие, ничего не возвращает

Поддерживаемые проверки в ветках:
- Точное значение: "OK" ->
- Группировка через запятую: "Low", "Medium" ->
- Диапазон: in 1..10 ->
- Принадлежность коллекции: in validSet ->
- Проверка типа: is String ->
- Отрицание: !in 10..20 ->, !is String ->
- Guard condition (Kotlin 2.1+): is Cat if !cat.hungry ->
!!!
## ПРИВЕДИТЕ ПРИМЕРЫ WHEN С РАЗНЫМИ ПАТТЕРНАМИ
---
Точное значение:

```kotlin
when (code) {
    200 -> "OK"
    404 -> "Not Found"
    else -> "Unknown"
}
```

Группировка через запятую (OR-логика):

```kotlin
when (priority) {
    "Low", "Medium" -> println("Стандартная обработка")
    "High" -> println("Срочная обработка")
}
```

Диапазон (in):

```kotlin
when (score) {
    in 90..100 -> "A"
    in 80..89 -> "B"
    !in 0..100 -> "Ошибка: вне диапазона"
    else -> "C"
}
```

Принадлежность коллекции (in):

```kotlin
val admins = setOf("root", "admin")
when (user) {
    in admins -> println("Полный доступ")
    else -> println("Ограниченный доступ")
}
```

Проверка типа (is) со smart cast:

```kotlin
fun length(input: Any): Int = when (input) {
    is String -> input.length
    is IntArray -> input.size
    else -> 0
}
```

Результат функции в ветке:

```kotlin
when (pin) {
    storedPin.toInt() -> println("PIN верный")
    else -> println("PIN неверный")
}
```

when без аргумента (замена if-else if):

```kotlin
when {
    x.isOdd() -> println("Нечётное")
    y.isEven() -> println("Чётное")
    else -> println("Другое")
}
```

Guard condition (Kotlin 2.1+) — дополнительное условие к ветке:

```kotlin
when (animal) {
    is Cat if !animal.mouseHunter -> feedCat()
    is Dog -> feedDog()
    else -> println("Неизвестное животное")
}
```
!!!
## КОГДА ИСПОЛЬЗОВАТЬ IF, А КОГДА WHEN?
---
if — для простых бинарных условий:
- Проверка true/false
- Ранний выход (early return / guard clause)
- Одно-два условия

```kotlin
if (user == null) return
val access = if (isAdmin) "full" else "limited"
```

when — для множественного ветвления:
- 3 и более веток по одному значению
- Проверка типа (is) со smart cast
- Проверка диапазонов и коллекций (in)
- Исчерпывающие проверки на enum/sealed class

```kotlin
val label = when (status) {
    Status.ACTIVE -> "Активен"
    Status.BLOCKED -> "Заблокирован"
    Status.DELETED -> "Удалён"
}
```

Правило: если пишешь цепочку else if больше двух — замени на when.
!!!
## ЧТО ТАКОЕ EXHAUSTIVE WHEN И КОГДА ОН ОБЯЗАТЕЛЕН?
---
Exhaustive when (исчерпывающий when) — when, в котором покрыты ВСЕ возможные значения аргумента. Компилятор гарантирует что ни один случай не пропущен.

Когда обязателен:

1. when как expression — ВСЕГДА должен быть исчерпывающим (компилятор должен знать что вернуть для любого значения)

2. when как statement (с Kotlin 1.7+) — обязателен для:
   - sealed class / sealed interface
   - enum class
   - Boolean

Типы с автоматической проверкой полноты (else не нужен):

```kotlin
// enum — компилятор знает все значения
enum class Direction { NORTH, SOUTH, EAST, WEST }

val label = when (direction) {
    Direction.NORTH -> "Север"
    Direction.SOUTH -> "Юг"
    Direction.EAST -> "Восток"
    Direction.WEST -> "Запад"
    // else не нужен — все случаи покрыты
}
```

```kotlin
// sealed class — компилятор знает все наследников
sealed class Result
class Success(val data: String) : Result()
class Error(val message: String) : Result()

fun handle(result: Result) = when (result) {
    is Success -> println(result.data)
    is Error -> println(result.message)
    // else не нужен — все наследники покрыты
}
```

Для остальных типов (String, Int и т.д.) — else обязателен при use как expression, потому что компилятор не может перечислить все возможные значения.

Зачем это важно: при добавлении нового варианта в enum/sealed class компилятор покажет ошибку в каждом when, где новый случай не обработан. Это защита от забытых веток.
!!!
## ЧТО ТАКОЕ SMART CAST И КАК ОН СВЯЗАН С УПРАВЛЯЮЩИМИ КОНСТРУКЦИЯМИ?
---
Smart cast — автоматическое приведение типа компилятором после проверки через is или проверки на null. Явный каст (as) не нужен.

Как работает с if:

```kotlin
fun printLength(data: Any) {
    if (data is String) {
        // data автоматически приведён к String
        println(data.length)
    }
}
```

Как работает с when:

```kotlin
fun process(input: Any) = when (input) {
    is String -> input.uppercase()
    is Int -> input + 1
    is IntArray -> input.sum()
    else -> "Неизвестный тип"
}
```

Smart cast при проверке на null:

```kotlin
fun greet(name: String?) {
    if (name != null) {
        // name автоматически приведён к String (не nullable)
        println(name.length)
    }
}
```

Smart cast с логическими операторами:

```kotlin
// После is-проверки через && — smart cast работает справа
if (x is String && x.length > 0) {
    println(x.uppercase())
}

// После !is-проверки через || — smart cast работает справа
if (x !is String || x.length == 0) return
```

Где smart cast работает:
- val локальные переменные — всегда
- var локальные переменные — если не изменены между проверкой и использованием, не захвачены изменяющей лямбдой
- val свойства класса — только private/internal в том же модуле, без custom getter, не open

Где smart cast НЕ работает:
- var свойства класса — никогда (могут быть изменены другим кодом)
- val с custom getter — getter может вернуть разное значение при повторном вызове
- open свойства — могут быть переопределены в наследнике
- Делегированные свойства

Обход ограничений — копирование в локальную переменную:

```kotlin
class Parser(var input: String?) {
    fun parse() {
        // ПЛОХО: smart cast невозможен для var свойства
        // if (input != null) println(input.length)

        // ХОРОШО: копируем в локальную val
        val local = input
        if (local != null) {
            println(local.length)
        }
    }
}
```

## ЧТО ТАКОЕ TYPE INFERENCE И КОГДА ИСПОЛЬЗОВАТЬ ЯВНЫЕ ТИПЫ?
---
Type inference (вывод типов) — способность компилятора автоматически определить тип переменной, параметра или возвращаемого значения без явного указания.

Где работает вывод типов:

```kotlin
val name = "Kotlin"           // String
var count = 0                 // Int
val pi = 3.14                 // Double
val items = listOf(1, 2, 3)  // List<Int>
```

Функции с одним выражением — возвращаемый тип выводится:

```kotlin
fun double(x: Int) = x * 2   // возвращает Int
```

Когда явный тип обязателен:

1. Отложенная инициализация (нет начального значения):

```kotlin
val name: String
name = "Kotlin"
```

2. Функции с телом в фигурных скобках — возвращаемый тип обязателен (кроме Unit):

```kotlin
fun sum(a: Int, b: Int): Int {
    return a + b
}
```

3. Пустые коллекции без контекста:

```kotlin
val list = emptyList<String>()  // тип элемента нельзя вывести
```

Когда явный тип рекомендуется (coding conventions):

- Публичный API (функции, свойства) — всегда указывать явно. Это делает контракт понятным и защищает от случайного изменения типа
- Platform types (Java interop) — явный тип обязателен в публичном API
- Kotlin поддерживает Explicit API mode — режим компилятора, который требует явных типов для всех публичных объявлений

Когда явный тип не нужен:

- Локальные переменные с инициализатором — тип очевиден
- Лямбда-параметры — тип выводится из контекста

```kotlin
// ХОРОШО: тип очевиден
val name = "Kotlin"

// ИЗБЫТОЧНО: тип дублирует инициализатор
val name: String = "Kotlin"
```
!!!
## АНТИПАТТЕРНЫ УПРАВЛЯЮЩИХ КОНСТРУКЦИЙ
---
1. Цепочки if-else if вместо when (3+ веток):

```kotlin
// ПЛОХО
if (status == "OK") { ... }
else if (status == "ERROR") { ... }
else if (status == "TIMEOUT") { ... }
else { ... }

// ХОРОШО
when (status) {
    "OK" -> ...
    "ERROR" -> ...
    "TIMEOUT" -> ...
    else -> ...
}
```

2. Небезопасный каст (as) вместо smart cast:

```kotlin
// ПЛОХО: ClassCastException при неверном типе
val str = input as String

// ХОРОШО: smart cast после проверки
if (input is String) {
    println(input.length)
}
```

3. Ручной каст после is-проверки (игнорирование smart cast):

```kotlin
// ПЛОХО: каст избыточен, smart cast уже сработал
if (input is String) {
    println((input as String).length)
}

// ХОРОШО: smart cast делает каст автоматически
if (input is String) {
    println(input.length)
}
```

4. when-expression без else для неперечислимых типов:

```kotlin
// ПЛОХО: не скомпилируется — String имеет бесконечное число значений
val label = when (status) {
    "OK" -> "Успех"
    "ERROR" -> "Ошибка"
}

// ХОРОШО: else покрывает остальные случаи
val label = when (status) {
    "OK" -> "Успех"
    "ERROR" -> "Ошибка"
    else -> "Неизвестно"
}
```

5. var свойство при smart cast:

```kotlin
// ПЛОХО: smart cast невозможен для var свойства
class Service(var data: Any?) {
    fun process() {
        if (data is String) {
            // println(data.length) — ошибка компиляции
        }
    }
}

// ХОРОШО: копируй в локальную переменную
class Service(var data: Any?) {
    fun process() {
        val local = data
        if (local is String) {
            println(local.length)
        }
    }
}
```

6. Избыточная явная типизация:

```kotlin
// ПЛОХО: тип очевиден из инициализатора
val count: Int = 0
val name: String = "Kotlin"
val items: List<Int> = listOf(1, 2, 3)

// ХОРОШО: компилятор выведет тип сам
val count = 0
val name = "Kotlin"
val items = listOf(1, 2, 3)
```

7. Исключения для управления потоком:

```kotlin
// ПЛОХО: исключение как замена условию
try {
    val value = map.getValue(key)
} catch (e: NoSuchElementException) {
    handleMissing()
}

// ХОРОШО: используй nullable / условные конструкции
val value = map[key] ?: handleMissing()
```
