## ЧТО ТАКОЕ ФУНКЦИЯ И КАК ОНА ОБЪЯВЛЯЕТСЯ В KOTLIN?
---
Функция — именованный блок кода, который выполняет определённую задачу. Принимает входные данные (параметры), выполняет логику и может возвращать результат.

Объявление через ключевое слово fun:

```kotlin
fun sum(a: Int, b: Int): Int {
    return a + b
}
```

Параметры записываются в формате имя: Тип (Pascal-нотация). Каждый параметр должен иметь явный тип. Параметры внутри функции — read-only (val), их нельзя переприсвоить.

Возвращаемый тип указывается после скобок через двоеточие. Если функция ничего полезного не возвращает — тип Unit (аналог void). Unit можно не писать:

```kotlin
// оба варианта эквивалентны
fun greet(name: String): Unit {
    println("Привет, $name")
}

fun greet(name: String) {
    println("Привет, $name")
}
```

Nothing — специальный тип для функций, которые никогда не завершаются нормально (всегда бросают исключение или содержат бесконечный цикл). Nothing является подтипом всех типов (bottom type), поэтому может использоваться в выражениях любого типа:

```kotlin
fun fail(message: String): Nothing {
    throw IllegalArgumentException(message)
}

// Nothing совместим с любым типом — работает в Elvis-операторе
val name: String = input ?: fail("Имя обязательно")
```

В Kotlin функции могут быть объявлены на верхнем уровне файла — класс не нужен (в отличие от Java).
!!!
## КАКИЕ ВИДЫ ПАРАМЕТРОВ ЕСТЬ У ФУНКЦИЙ?
---
Три вида параметров: обычные, с значением по умолчанию и vararg.

1. Значения по умолчанию (default values) — если аргумент не передан, используется значение из объявления:

```kotlin
fun connect(host: String, port: Int = 5432, ssl: Boolean = true) {
    println("$host:$port, ssl=$ssl")
}

connect("localhost")              // localhost:5432, ssl=true
connect("localhost", 3306)        // localhost:3306, ssl=true
connect("localhost", 3306, false) // localhost:3306, ssl=false
```

Это позволяет избежать множества перегрузок функций (как в Java).

2. Именованные аргументы (named arguments) — при вызове можно указать имя параметра. Это повышает читаемость и позволяет передавать аргументы в произвольном порядке:

```kotlin
connect(host = "localhost", ssl = false)
connect(ssl = false, host = "db.example.com")
```

С Kotlin 1.4 именованные и позиционные аргументы можно смешивать в любом порядке, если общая последовательность параметров сохранена:

```kotlin
fun reformat(str: String, uppercase: Boolean = true, separator: Char = ' ') { }

// именованный аргумент в середине — ОК с Kotlin 1.4
reformat("text", uppercase = false, '-')
```

3. vararg — переменное количество аргументов одного типа. Внутри функции доступен как Array:

```kotlin
fun printAll(vararg messages: String) {
    for (msg in messages) {
        println(msg)
    }
}

printAll("Привет", "Мир", "Kotlin")
```

Чтобы передать массив в vararg, используется оператор spread (*):

```kotlin
val words = arrayOf("Раз", "Два", "Три")
printAll(*words)
```

vararg может быть только один на функцию. Если он не последний параметр — остальные передаются через именованные аргументы.
!!!
## ЧТО ТАКОЕ SINGLE-EXPRESSION FUNCTIONS?
---
Single-expression function (функция-выражение) — функция, тело которой состоит из одного выражения. Вместо фигурных скобок и return используется знак =:

```kotlin
fun double(x: Int): Int = x * 2
```

Возвращаемый тип можно опустить — компилятор выведет его из выражения:

```kotlin
fun double(x: Int) = x * 2
```

Когда использовать:
- Функция содержит одно выражение
- Логика простая и умещается в одну строку
- Преобразование или вычисление

```kotlin
fun isAdult(age: Int) = age >= 18
fun fullName(first: String, last: String) = "$first $last"
fun max(a: Int, b: Int) = if (a > b) a else b
```

Когда НЕ использовать:
- Функция содержит несколько шагов
- Выражение слишком длинное и ухудшает читаемость
- Публичный API — рекомендуется указывать явный возвращаемый тип

Важно: для функций с блочным телом (фигурные скобки) возвращаемый тип обязателен (кроме Unit). Для single-expression — компилятор выводит тип сам.
!!!
## ЧТО ТАКОЕ ЛОКАЛЬНЫЕ ФУНКЦИИ?
---
Локальная функция — функция объявленная внутри другой функции. Видна только в пределах внешней функции.

```kotlin
fun processOrder(order: Order) {
    fun validate(order: Order) {
        require(order.amount > 0) { "Сумма должна быть положительной" }
    }

    validate(order)
    println("Заказ обработан: ${order.id}")
}
```

Ключевое свойство: локальная функция имеет доступ к переменным внешней функции (замыкание):

```kotlin
fun countPositive(numbers: List<Int>): Int {
    var count = 0
    fun check(n: Int) {
        if (n > 0) count++ // доступ к count из внешней функции
    }
    numbers.forEach { check(it) }
    return count
}
```

Когда использовать:
- Логика нужна только внутри одной функции
- Хочешь разбить длинную функцию на части без создания методов класса
- Нужен доступ к локальным переменным внешней функции

Когда НЕ использовать:
- Логика может понадобиться в других местах — выноси в обычную функцию
- Вложенность больше одного уровня — ухудшает читаемость
!!!
## ЧТО ТАКОЕ EXTENSION FUNCTIONS И ЗАЧЕМ ОНИ НУЖНЫ?
---
Extension function (функция-расширение) — функция, которая добавляет новое поведение к существующему классу без его изменения и наследования.

Синтаксис: перед именем функции указывается тип-получатель (receiver type):

```kotlin
fun String.addExclamation(): String {
    return this + "!"
}

println("Привет".addExclamation()) // Привет!
```

this внутри extension function ссылается на объект-получатель (тот, на котором вызвана функция).

Практические примеры:

```kotlin
fun Int.isEven() = this % 2 == 0

fun List<Int>.secondOrNull(): Int? = if (size >= 2) this[1] else null

println(4.isEven())                      // true
println(listOf(10, 20, 30).secondOrNull()) // 20
```

Как это работает: extension functions разрешаются статически (в compile time). Они НЕ модифицируют класс и НЕ добавляют в него метод. Под капотом это обычная статическая функция, которая принимает объект-получатель первым параметром.

Следствия статического разрешения:

```kotlin
open class Shape
class Circle : Shape()

fun Shape.name() = "Фигура"
fun Circle.name() = "Круг"

fun printName(shape: Shape) {
    println(shape.name())
}

printName(Circle()) // Фигура — вызвана Shape.name(), не Circle.name()
```

Тип определяется по переменной в compile time, а не по реальному объекту в runtime.

Ограничения:
- Нет доступа к private и protected членам класса
- Если у класса есть метод с такой же сигнатурой — метод класса побеждает
- Не являются полиморфными (статическая диспетчеризация)

Зачем нужны:
- Добавить утилитные функции к типам которые ты не контролируешь (String, List, Int)
- Улучшить читаемость: obj.doSomething() вместо doSomething(obj)
- Альтернатива утилитным классам (StringUtils, CollectionUtils)
!!!
## ЧТО ТАКОЕ INFIX ФУНКЦИИ?
---
Infix функция — функция, которую можно вызвать без точки и скобок, в инфиксной нотации: объект функция аргумент.

Требования:
- Ключевое слово infix перед fun
- Должна быть функцией-членом или extension function
- Ровно один параметр (без значения по умолчанию и без vararg)

```kotlin
infix fun Int.power(exponent: Int): Int {
    var result = 1
    repeat(exponent) { result *= this }
    return result
}

// два способа вызова
val a = 2.power(10)    // обычный
val b = 2 power 10     // инфиксный
```

Встроенные infix функции в Kotlin:

```kotlin
val pair = "key" to "value"       // Pair
val inRange = 5 in 1..10          // contains
val shifted = 1 shl 2             // побитовый сдвиг
val result = true and false       // логическое И
val bits = 0xFF xor 0x0F          // побитовый XOR
```

Приоритет: инфиксные вызовы имеют более низкий приоритет чем арифметические операторы и type cast, но более высокий чем логические операторы && и ||.

Когда использовать:
- DSL и читаемый код (1 to "one", request shouldReturn 200)
- Когда инфиксная запись естественно читается как предложение
!!!
## ЧТО ТАКОЕ OPERATOR FUNCTIONS?
---
Operator function — функция, помеченная ключевым словом operator, которая позволяет использовать операторы (+, -, *, [], () и другие) с пользовательскими типами.

Kotlin не позволяет создавать произвольные операторы — только перегружать предопределённый набор.

```kotlin
data class Point(val x: Int, val y: Int) {
    operator fun plus(other: Point) = Point(x + other.x, y + other.y)
    operator fun unaryMinus() = Point(-x, -y)
}

val p1 = Point(1, 2)
val p2 = Point(3, 4)
println(p1 + p2)   // Point(x=4, y=6)
println(-p1)       // Point(x=-1, y=-2)
```

Основные операторы и соответствующие функции:

Арифметические:
- a + b -> a.plus(b)
- a - b -> a.minus(b)
- a * b -> a.times(b)
- a / b -> a.div(b)
- a % b -> a.rem(b)

Унарные:
- -a -> a.unaryMinus()
- +a -> a.unaryPlus()
- !a -> a.not()

Доступ по индексу:
- a[i] -> a.get(i)
- a[i] = v -> a.set(i, v)

Вызов как функция:
- a() -> a.invoke()
- a(x) -> a.invoke(x)

Сравнение:
- a > b -> a.compareTo(b) > 0
- a == b -> a?.equals(b) ?: (b === null)

Присваивание с операцией:
- a += b -> a.plusAssign(b)

in:
- a in b -> b.contains(a)

Операторы можно определять как member функции или как extension functions.
!!!
## ЧТО ТАКОЕ ФУНКЦИИ ВЫСШЕГО ПОРЯДКА?
---
Функция высшего порядка (higher-order function) — функция, которая принимает другую функцию как параметр или возвращает функцию.

Это возможно потому что в Kotlin функции являются first-class citizens (объектами первого класса) — их можно хранить в переменных, передавать как аргументы и возвращать из функций.

Функция как параметр:

```kotlin
fun operate(a: Int, b: Int, operation: (Int, Int) -> Int): Int {
    return operation(a, b)
}

val result = operate(10, 5) { a, b -> a + b }
println(result) // 15
```

(Int, Int) -> Int — это тип функции: принимает два Int, возвращает Int.

Функция как возвращаемое значение:

```kotlin
fun multiplier(factor: Int): (Int) -> Int {
    return { number -> number * factor }
}

val triple = multiplier(3)
println(triple(5))  // 15
println(triple(10)) // 30
```

Встроенные higher-order functions для коллекций:

```kotlin
val numbers = listOf(1, 2, 3, 4, 5)

numbers.filter { it > 2 }          // [3, 4, 5]
numbers.map { it * 2 }             // [2, 4, 6, 8, 10]
numbers.fold(0) { acc, n -> acc + n } // 15
numbers.any { it > 4 }             // true
numbers.sortedBy { -it }           // [5, 4, 3, 2, 1]
```

Зачем нужны:
- Абстрагирование повторяющейся логики (паттерн "стратегия")
- Функциональный стиль обработки данных (filter, map, reduce)
- Создание DSL
!!!
## ЧТО ТАКОЕ ЛЯМБДА-ВЫРАЖЕНИЯ И АНОНИМНЫЕ ФУНКЦИИ?
---
Лямбда-выражение (lambda expression) — анонимная функция, которая записывается как литерал и может быть передана как значение.

Синтаксис: { параметры -> тело }

```kotlin
val sum = { a: Int, b: Int -> a + b }
println(sum(3, 4)) // 7
```

Последнее выражение в лямбде — это возвращаемое значение. Явный return не нужен (и обычно не используется).

Trailing lambda — если последний параметр функции — лямбда, её можно вынести за скобки:

```kotlin
// обычный вызов
listOf(1, 2, 3).filter({ it > 1 })

// trailing lambda
listOf(1, 2, 3).filter { it > 1 }

// если лямбда — единственный аргумент, скобки можно убрать
run { println("Привет") }
```

it — неявное имя единственного параметра:

```kotlin
listOf("a", "b", "c").map { it.uppercase() } // [A, B, C]
```

Деструктуризация в лямбде:

```kotlin
val map = mapOf("a" to 1, "b" to 2)
map.forEach { (key, value) -> println("$key = $value") }
```

Неиспользуемый параметр — заменяется на _:

```kotlin
map.forEach { (_, value) -> println(value) }
```

Анонимная функция — альтернатива лямбде с явным указанием типов и return:

```kotlin
val double = fun(x: Int): Int {
    return x * 2
}
```

Разница между лямбдой и анонимной функцией:
- return в лямбде — возврат из внешней функции (non-local return)
- return в анонимной функции — возврат только из самой анонимной функции
!!!
## ЧТО ТАКОЕ FUNCTION TYPES И FUNCTION REFERENCES?
---
Function type (тип функции) — тип, описывающий сигнатуру функции: какие параметры принимает и что возвращает.

Синтаксис: (ТипПараметра1, ТипПараметра2) -> ТипВозврата

```kotlin
val operation: (Int, Int) -> Int = { a, b -> a + b }
val predicate: (String) -> Boolean = { it.isNotEmpty() }
val action: () -> Unit = { println("Готово") }
```

Function type с receiver — функция, у которой есть объект-получатель (как extension function):

```kotlin
val greet: String.() -> String = { "Привет, $this!" }
println("Мир".greet()) // Привет, Мир!
```

Nullable function type — функция может быть null:

```kotlin
val callback: ((String) -> Unit)? = null
callback?.invoke("тест") // безопасный вызов
```

Function reference (ссылка на функцию) — оператор :: позволяет передать существующую функцию как значение:

```kotlin
fun isPositive(n: Int) = n > 0

val numbers = listOf(-2, -1, 0, 1, 2)
println(numbers.filter(::isPositive)) // [1, 2]
```

Виды ссылок:

```kotlin
// ссылка на top-level функцию
::isPositive

// bound reference — привязана к конкретному экземпляру
val str = "Kotlin"
str::uppercase

// unbound reference — без привязки, receiver передаётся первым параметром
String::uppercase

// ссылка на конструктор
::Person

// ссылка на свойство
Person::name
```

Когда использовать function reference вместо лямбды:
- Функция уже существует — нет смысла оборачивать в лямбду
- Читаемость: numbers.filter(::isPositive) понятнее чем numbers.filter { isPositive(it) }
!!!
## ЧТО ТАКОЕ INLINE ФУНКЦИИ И ЗАЧЕМ ОНИ НУЖНЫ?
---
Inline функция — функция, помеченная ключевым словом inline. Компилятор подставляет тело функции и тело переданных лямбд прямо в место вызова, вместо создания объекта-функции и вызова через invoke().

Зачем: при каждом вызове higher-order функции для лямбды создаётся объект в куче. Если функция вызывается часто (в цикле, в горячем пути) — это лишняя нагрузка на GC. inline устраняет эти расходы.

```kotlin
inline fun measure(block: () -> Unit) {
    val start = System.nanoTime()
    block()
    val end = System.nanoTime()
    println("Время: ${end - start} нс")
}

// при компиляции тело measure и лямбды встраивается в место вызова
measure {
    listOf(1, 2, 3).sum()
}
```

noinline — запрещает инлайнинг конкретной лямбды (если нужно сохранить её как объект):

```kotlin
inline fun doWork(inlined: () -> Unit, noinline stored: () -> Unit) {
    inlined()            // встраивается
    val ref = stored     // сохраняется как объект — нельзя инлайнить
    ref()
}
```

crossinline — лямбда будет инлайниться, но non-local return из неё запрещён (нужно когда лямбда вызывается из другого контекста):

```kotlin
inline fun runInThread(crossinline block: () -> Unit) {
    Thread {
        block() // вызов из другого потока — non-local return невозможен
    }.start()
}
```

reified — позволяет обращаться к generic-типу в runtime (только в inline функциях):

```kotlin
inline fun <reified T> isType(value: Any): Boolean {
    return value is T // без reified это невозможно из-за type erasure
}

println(isType<String>("hello")) // true
println(isType<Int>("hello"))    // false
```

Когда использовать inline:
- Функция принимает лямбду и вызывается часто
- Нужен reified для работы с типами в runtime
- Стандартные scope functions (let, run, apply, also, with) — все inline

Когда НЕ использовать:
- Большое тело функции без лямбда-параметров — раздует байткод
- Функция вызывается редко — выигрыш незначителен
!!!
## ЧТО ТАКОЕ SCOPE FUNCTIONS (let, run, with, apply, also)?
---
Scope functions — пять стандартных inline функций, которые выполняют блок кода в контексте объекта. Отличаются способом доступа к объекту и возвращаемым значением.

Два отличия между ними:
1. Как ссылаются на объект: this (receiver) или it (аргумент)
2. Что возвращают: сам объект или результат лямбды

let — объект как it, возвращает результат лямбды:

```kotlin
val length = "Kotlin".let {
    println("Строка: $it")
    it.length // возвращаемое значение
}
// length = 6
```

Типичное применение — null-проверка:
```kotlin
val name: String? = "Kotlin"
name?.let { println("Длина: ${it.length}") }
```

run — объект как this, возвращает результат лямбды:

```kotlin
val result = service.run {
    port = 8080              // this.port
    query(prepareRequest())  // возвращаемое значение
}
```

with — объект как this, возвращает результат лямбды. Не extension function — объект передаётся аргументом:

```kotlin
val info = with(config) {
    "host=$host, port=$port" // this.host, this.port
}
```

apply — объект как this, возвращает сам объект:

```kotlin
val person = Person("Иван").apply {
    age = 25         // this.age
    city = "Москва"  // this.city
}
// person — тот же объект с заполненными полями
```

Типичное применение — инициализация/конфигурация объекта.

also — объект как it, возвращает сам объект:

```kotlin
val numbers = mutableListOf(1, 2, 3).also {
    println("Список создан: $it") // побочное действие
}
// numbers — тот же список
```

Типичное применение — побочные действия (логирование, отладка).

Краткая шпаргалка:
- Конфигурация объекта -> apply
- Вычисление на объекте -> run
- Группировка вызовов -> with
- Null-проверка + преобразование -> let
- Побочные действия -> also
!!!
## ЧТО ТАКОЕ РЕКУРСИЯ И TAILREC В KOTLIN?
---
Рекурсия — приём программирования, при котором функция вызывает саму себя для решения подзадачи.

Любая рекурсия имеет:
- Базовый случай (base case) — условие остановки
- Рекурсивный случай — вызов самой себя с меньшей задачей

```kotlin
fun factorial(n: Int): Long {
    if (n <= 1) return 1            // базовый случай
    return n * factorial(n - 1)     // рекурсивный случай
}
```

Проблема: каждый рекурсивный вызов добавляет кадр в стек вызовов. При глубокой рекурсии (например, factorial(100000)) — StackOverflowError.

tailrec — модификатор, который оптимизирует хвостовую рекурсию в цикл. Компилятор заменяет рекурсивные вызовы на итерацию — стек не растёт.

Хвостовая рекурсия (tail recursion) — рекурсивный вызов является последней операцией в функции (после него ничего не выполняется).

```kotlin
// ПЛОХО: НЕ хвостовая — после factorial есть умножение n *
fun factorial(n: Int): Long {
    if (n <= 1) return 1
    return n * factorial(n - 1)
}

// ХОРОШО: хвостовая — рекурсивный вызов последний
tailrec fun factorial(n: Int, acc: Long = 1): Long {
    if (n <= 1) return acc
    return factorial(n - 1, n * acc)
}
```

Паттерн: промежуточный результат передаётся через аккумулятор (acc), а не вычисляется после возврата.

Требования для tailrec:
- Рекурсивный вызов — последняя операция (no operations after)
- Нельзя использовать в try/catch/finally
- Функция не может быть open (переопределяемой)

Если пометить функцию tailrec, но она не является хвостовой — компилятор выдаст предупреждение.

Примеры:

```kotlin
// сумма списка через tailrec
tailrec fun sumList(list: List<Int>, acc: Int = 0): Int {
    if (list.isEmpty()) return acc
    return sumList(list.drop(1), acc + list.first())
}

// числа Фибоначчи через tailrec
tailrec fun fib(n: Int, a: Long = 0, b: Long = 1): Long {
    if (n == 0) return a
    return fib(n - 1, b, a + b)
}
```

## ЧТО ТАКОЕ ЧИСТЫЕ ФУНКЦИИ И ПОБОЧНЫЕ ЭФФЕКТЫ?
---
Это общий концепт программирования, не специфичный для Kotlin.

Чистая функция (pure function) — функция, которая:
1. При одинаковых входных данных всегда возвращает одинаковый результат
2. Не имеет побочных эффектов (не изменяет ничего за пределами своего тела)

```kotlin
// чистая — результат зависит только от аргументов
fun sum(a: Int, b: Int) = a + b

// чистая — нет побочных эффектов
fun format(name: String) = "Привет, $name!"
```

Побочный эффект (side effect) — любое изменение состояния за пределами функции:
- Изменение глобальной/внешней переменной
- Запись в файл, базу данных, сеть
- Вывод в консоль (println)
- Изменение переданного мутабельного объекта

```kotlin
var counter = 0

// НЕ чистая — изменяет внешнюю переменную
fun increment(): Int {
    counter++
    return counter
}

// НЕ чистая — результат зависит от внешнего состояния
fun getCount() = counter
```

Почему чистые функции полезны:
- Предсказуемость — легко понять что функция делает
- Тестируемость — не нужно настраивать окружение
- Безопасность в многопоточности — нет разделяемого состояния
- Кэширование — результат можно сохранить для повторного использования

На практике программа не может состоять только из чистых функций (нужен ввод/вывод, работа с БД). Рекомендация: выделять чистую логику в отдельные функции, а побочные эффекты изолировать на границах (ввод/вывод, UI).

```kotlin
// чистая логика
fun calculateDiscount(price: Double, percent: Int): Double {
    return price * (1 - percent / 100.0)
}

// побочный эффект — отдельно
fun applyDiscount(order: Order) {
    val newPrice = calculateDiscount(order.price, order.discount)
    database.update(order.id, newPrice) // побочный эффект
}
```

## ЧТО ТАКОЕ ЗАМЫКАНИЕ (CLOSURE)?
---
Это общий концепт программирования, реализованный в Kotlin.

Замыкание (closure) — функция (или лямбда), которая захватывает переменные из окружающего контекста и может обращаться к ним даже после того как этот контекст завершился.

```kotlin
fun counter(): () -> Int {
    var count = 0
    return { ++count }  // лямбда захватывает переменную count
}

val next = counter()
println(next()) // 1
println(next()) // 2
println(next()) // 3
```

Переменная count живёт не на стеке функции counter(), а перемещается в объект-обёртку, потому что лямбда ссылается на неё.

Важное отличие Kotlin от Java: в Kotlin лямбда может захватывать и изменять var переменные. В Java — только effectively final (фактически неизменяемые).

```kotlin
fun countMatches(list: List<String>, prefix: String): Int {
    var count = 0
    list.forEach {
        if (it.startsWith(prefix)) count++ // изменяем захваченную переменную
    }
    return count
}
```

Где замыкания используются:
- Лямбды в higher-order functions (forEach, map, filter)
- Callback-функции
- Фабрики функций (как пример counter() выше)
- Локальные функции (имеют доступ к переменным внешней функции)

Отличие от некоторых языков — захват переменной цикла:

```kotlin
val actions = mutableListOf<() -> Unit>()
for (i in 0..2) {
    actions.add { println(i) }
}
actions.forEach { it() } // 0, 1, 2

// В Kotlin for-переменная фактически val на каждой итерации —
// каждая лямбда захватывает своё значение.
// В JavaScript (var) все лямбды напечатали бы 3 (одна общая переменная).
```

## АНТИПАТТЕРНЫ ФУНКЦИЙ
---
1. Слишком много параметров (больше 3-4):

```kotlin
// ПЛОХО
fun createUser(name: String, age: Int, email: String, city: String, phone: String, role: String) { }

// ХОРОШО — объединить в data class
data class UserParams(val name: String, val age: Int, val email: String, val city: String)

fun createUser(params: UserParams) { }
```

2. Игнорирование именованных аргументов при неочевидных параметрах:

```kotlin
// ПЛОХО — непонятно что значат true и false
setFeature("darkMode", true, false)

// ХОРОШО
setFeature(name = "darkMode", enabled = true, persistent = false)
```

3. Глубокая вложенность вместо раннего возврата:

```kotlin
// ПЛОХО
fun process(user: User?) {
    if (user != null) {
        if (user.isActive) {
            if (user.hasPermission) {
                doWork(user)
            }
        }
    }
}

// ХОРОШО — guard clauses (ранний возврат)
fun process(user: User?) {
    if (user == null) return
    if (!user.isActive) return
    if (!user.hasPermission) return
    doWork(user)
}
```

4. Побочные эффекты в single-expression function:

```kotlin
// ПЛОХО — выглядит как чистая функция, но имеет побочный эффект
fun getUser(id: Int) = database.findById(id).also { log.info("Fetched $id") }

// ХОРОШО — побочный эффект явный в блочном теле
fun getUser(id: Int): User {
    val user = database.findById(id)
    log.info("Fetched $id")
    return user
}
```

5. Злоупотребление scope functions (вложенные let/run/apply):

```kotlin
// ПЛОХО — нечитаемо
user?.let { u ->
    u.address?.let { addr ->
        addr.city?.let { city ->
            println(city)
        }
    }
}

// ХОРОШО — безопасная цепочка
val city = user?.address?.city
if (city != null) println(city)
```

6. Extension function для нерелевантного типа:

```kotlin
// ПЛОХО — при чём тут String?
fun String.saveToDatabase() { }

// ХОРОШО — extension для типа к которому функция относится
fun User.save() { }
```

7. Использование лямбды вместо function reference:

```kotlin
// ИЗБЫТОЧНО
list.map { it.toString() }
list.filter { isValid(it) }

// ХОРОШО
list.map(Any::toString)
list.filter(::isValid)
```
