## КАК РАБОТАЕТ ПРОВЕРКА ТИПОВ И СРАВНЕНИЕ В KOTLIN?
---
is / !is — проверка типа с автоматическим smart cast:

```kotlin
val obj: Any = "hello"

if (obj is String) {
    println(obj.length) // obj уже String — smart cast
}

if (obj !is String) {
    println("Не строка")
}
```

== / != — сравнение по значению (вызывает equals()):

```kotlin
val list1 = listOf(1, 2, 3)
val list2 = listOf(1, 2, 3)
println(list1 == list2)  // true — содержимое одинаковое
```

=== / !== — сравнение по ссылке (один ли это объект в памяти):

```kotlin
val a = listOf(1, 2, 3)
val b = listOf(1, 2, 3)
val c = a

println(a === b)  // false — разные объекты
println(a === c)  // true — одна и та же ссылка
```

## ЧТО ТАКОЕ DATA CLASS И ЧТО ОН ГЕНЕРИРУЕТ?
---
```kotlin
data class User(val name: String, val age: Int)
```

Автоматически генерирует:
- equals() — сравнение по полям
- hashCode() — хеш на основе полей
- toString() — User(name=Alice, age=25)
- copy() — копирование с изменением полей
- component1(), component2() — для деструктуризации

Зачем нужен data class для коллекций:

Без data class — объекты сравниваются по ссылке:

```kotlin
class User(val id: Int, val name: String)

val user1 = User(1, "Alice")
val user2 = User(1, "Alice")
val set = setOf(user1)
println(set.contains(user2))  // false! Разные объекты в памяти
```

С data class — объекты сравниваются по содержимому:

```kotlin
data class User(val id: Int, val name: String)

val user1 = User(1, "Alice")
val user2 = User(1, "Alice")
val set = setOf(user1)
println(set.contains(user2))  // true! Содержимое одинаковое
```

copy() — копирование с изменениями:

```kotlin
val alice = User("Alice", 25)
val olderAlice = alice.copy(age = 30)
// User(name=Alice, age=30)
```

Важно: copy() создаёт shallow copy — вложенные объекты не копируются:

```kotlin
data class User(val name: String, val address: Address)
data class Address(var city: String)

val user1 = User("Alice", Address("NYC"))
val user2 = user1.copy()
user2.address.city = "LA"
println(user1.address.city)  // "LA" — изменилось и у user1!
```

equals/hashCode используют только primary constructor:

```kotlin
data class Person(val name: String) {
    var age: Int = 0  // НЕ участвует в equals/hashCode!
}

val p1 = Person("John").apply { age = 25 }
val p2 = Person("John").apply { age = 30 }
println(p1 == p2)  // true — age не учитывается
```

## ЧТО ТАКОЕ ДЕСТРУКТУРИЗАЦИЯ?
---
Разбирает объект на составные части через componentN() функции.

Pair и Triple:

```kotlin
val pair = "Alice" to 25
val (name, age) = pair

val triple = Triple("Alice", 25, "Dev")
val (n, a, job) = triple
```

Data class:

```kotlin
data class User(val name: String, val age: Int)
val user = User("Alice", 25)
val (name, age) = user
```

В циклах по Map:

```kotlin
val map = mapOf("a" to 1, "b" to 2)

for ((key, value) in map) {
    println("$key = $value")
}

map.forEach { (key, value) ->
    println("$key = $value")
}
```

Пропуск ненужных компонентов:

```kotlin
val (name, _) = user  // age не нужен
```

## КАК УСТРОЕНА ИЕРАРХИЯ КОЛЛЕКЦИЙ?
---
```
Iterable<T>
│
├── Collection<T>
│   ├── List<T>
│   └── Set<T>
│
└── MutableIterable<T>
    └── MutableCollection<T>
        ├── MutableList<T>
        └── MutableSet<T>

Map<K,V>  (отдельно, не Iterable!)
└── MutableMap<K,V>
```

Ключевое:
- List, Set, Map — read-only интерфейсы
- MutableList, MutableSet, MutableMap — с методами изменения
- Map не наследует Iterable, но можно итерировать по entries, keys, values
!!!
## ЧТО ТАКОЕ КОНТРАКТ EQUALS И HASHCODE?
---
Правило: если a == b (equals), то a.hashCode() == b.hashCode()

Нарушение ломает HashSet и HashMap:

```kotlin
class BadUser(val id: Int) {
    override fun equals(other: Any?) =
        other is BadUser && id == other.id
    // hashCode НЕ переопределён — ОШИБКА!
}

val set = hashSetOf(BadUser(1))
println(set.contains(BadUser(1)))  // false! Разные hashCode → разные bucket'ы
```

Решение: всегда используй data class или переопределяй оба метода.

## КАК РАБОТАЕТ ПЕРЕГРУЗКА ОПЕРАТОРОВ?
---
Kotlin позволяет определять поведение операторов через operator fun.

Основные операторы:
- a + b → a.plus(b)
- a - b → a.minus(b)
- a * b → a.times(b)
- a / b → a.div(b)
- a == b → a.equals(b)
- a < b → a.compareTo(b) < 0
- a in b → b.contains(a)
- a[i] → a.get(i)
- a[i] = x → a.set(i, x)

Пример — Vector:

```kotlin
data class Vector(val x: Int, val y: Int) {
    operator fun plus(other: Vector) = Vector(x + other.x, y + other.y)
    operator fun minus(other: Vector) = Vector(x - other.x, y - other.y)
}

val v1 = Vector(1, 2)
val v2 = Vector(3, 4)
println(v1 + v2)  // Vector(4, 6)
```

Пример — compareTo для сравнений:

```kotlin
data class Version(val major: Int, val minor: Int) : Comparable<Version> {
    override fun compareTo(other: Version): Int {
        return when {
            major != other.major -> major - other.major
            else -> minor - other.minor
        }
    }
}

val v1 = Version(1, 2)
val v2 = Version(2, 0)
println(v1 < v2)  // true
```

## ЧТО ДЕЛАЮТ SCOPE-ФУНКЦИИ LET, ALSO, APPLY, RUN?
---
let — преобразование (принимает it, возвращает результат лямбды):

```kotlin
val length = name?.let { it.length }
```

also — побочный эффект (принимает it, возвращает исходный объект):

```kotlin
val user = User("Alice").also { println("Created: $it") }
```

apply — настройка объекта (принимает this, возвращает исходный объект):

```kotlin
val user = User().apply {
    name = "Alice"
    age = 25
}
```

run — выполнение блока с результатом (принимает this, возвращает результат лямбды):

```kotlin
val result = user.run { "$name is $age years old" }
```

Elvis оператор ?::

```kotlin
val name: String? = null
val result = name ?: "default"  // "default"
```
