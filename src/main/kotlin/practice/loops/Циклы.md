## ЧТО ТАКОЕ ЦИКЛЫ В KOTLIN И КАКИЕ ВИДЫ БЫВАЮТ?
---
Цикл — конструкция которая повторяет блок кода пока выполняется условие или пока не закончатся элементы.

В Kotlin три вида циклов:

1. for — перебор элементов (коллекции, диапазоны, строки)

```kotlin
for (item in collection) {
    println(item)
}
```

2. while — повторение ПОКА условие истинно, проверка ДО выполнения тела

```kotlin
while (condition) {
    // тело
}
```

3. do-while — повторение ПОКА условие истинно, проверка ПОСЛЕ выполнения тела (тело выполнится минимум один раз)

```kotlin
do {
    // тело
} while (condition)
```

Ключевое отличие от многих языков: for в Kotlin не имеет классической формы for (i = 0; i < n; i++). Вместо этого используется for-in с итерируемым объектом.

Также существует функция repeat(n) — не цикл в строгом смысле, а стандартная функция которая выполняет блок n раз:

```kotlin
repeat(3) {
    println("Привет")
}
// Привет
// Привет
// Привет
```

## КАК РАБОТАЕТ ЦИКЛ FOR И ЧТО ТАКОЕ RANGES?
---
for в Kotlin работает только через in — перебирает всё что предоставляет итератор.

Диапазоны (ranges) — способ задать последовательность значений для перебора.

Виды диапазонов:

1. Закрытый (включая оба конца):
```kotlin
for (i in 1..5) print(i)  // 12345
```

2. Открытый (не включая конец):
```kotlin
for (i in 1..<5) print(i)  // 1234
```

Также можно использовать until (делает то же самое):
```kotlin
for (i in 1 until 5) print(i)  // 1234
```

3. Обратный порядок:
```kotlin
for (i in 5 downTo 1) print(i)  // 54321
```

4. С шагом:
```kotlin
for (i in 0..10 step 3) print("$i ")  // 0 3 6 9
for (i in 10 downTo 0 step 2) print("$i ")  // 10 8 6 4 2 0
```

Диапазоны работают не только с числами:
```kotlin
for (c in 'a'..'d') print(c)  // abcd
```

Перебор коллекций:
```kotlin
val items = listOf("яблоко", "банан", "киви")
for (item in items) {
    println(item)
}
```

Перебор с индексом — withIndex():
```kotlin
val items = listOf("яблоко", "банан", "киви")
for ((index, value) in items.withIndex()) {
    println("$index: $value")
}
// 0: яблоко
// 1: банан
// 2: киви
```

Перебор только по индексам:
```kotlin
for (i in items.indices) {
    println(items[i])
}
```

Деструктуризация в for:
```kotlin
val map = mapOf("a" to 1, "b" to 2)
for ((key, value) in map) {
    println("$key -> $value")
}
```

## КАК РАБОТАЕТ WHILE И DO-WHILE?
---
while — проверяет условие ДО выполнения тела. Если условие сразу ложно, тело не выполнится ни разу.

```kotlin
var x = 5
while (x > 0) {
    println(x)
    x--
}
// 5 4 3 2 1
```

do-while — выполняет тело, потом проверяет условие. Тело выполнится минимум один раз, даже если условие изначально ложно.

```kotlin
var x = 0
do {
    println(x)
    x++
} while (x < 3)
// 0 1 2
```

Важная особенность do-while: переменные объявленные внутри тела видны в условии.

```kotlin
do {
    val input = readlnOrNull()
} while (input != "exit")
```

В while это невозможно — условие проверяется до входа в тело, поэтому переменная из тела ещё не существует.

Когда использовать do-while:
- Нужно выполнить действие хотя бы раз до проверки (ввод пользователя, бросок кубика)
- Переменная для условия создаётся внутри тела

Бесконечный цикл:

```kotlin
while (true) {
    // выполняется пока не встретит break или return
}
```

Бесконечный цикл без условия выхода — антипаттерн (примеры в вопросе "Антипаттерны циклов").
!!!
## ЧТО ТАКОЕ ИТЕРИРОВАНИЕ И ПО КАКИМ ТИПАМ МОЖНО ИТЕРИРОВАТЬ?
---
Итерирование — последовательный перебор элементов один за другим.

В основе лежит протокол итератора — объект должен предоставить функцию iterator(), которая возвращает Iterator с двумя методами:
- hasNext() — есть ли следующий элемент
- next() — вернуть следующий элемент

Когда пишешь for (item in something), компилятор вызывает something.iterator() и дальше hasNext()/next() под капотом.

Типы по которым можно итерировать:

1. Коллекции — List, Set, Map:
```kotlin
val list = listOf(1, 2, 3)
for (item in list) println(item)

val map = mapOf("a" to 1, "b" to 2)
for ((key, value) in map) println("$key -> $value")
```

2. Массивы:
```kotlin
val arr = arrayOf("x", "y", "z")
for (item in arr) println(item)
```

3. Строки (как последовательность Char):
```kotlin
for (c in "Kotlin") print(c)  // Kotlin
```

4. Диапазоны и прогрессии:
```kotlin
for (i in 1..5) print(i)       // 12345
for (c in 'a'..'d') print(c)   // abcd
```

5. Любой объект у которого есть operator fun iterator():
```kotlin
class Countdown(val start: Int) {
    operator fun iterator(): Iterator<Int> {
        var current = start
        return object : Iterator<Int> {
            override fun hasNext() = current > 0
            override fun next() = current--
        }
    }
}

for (i in Countdown(3)) print(i)  // 321
```

Явное использование итератора (без for):
```kotlin
val numbers = listOf("один", "два", "три")
val iter = numbers.iterator()
while (iter.hasNext()) {
    println(iter.next())
}
```

Итератор одноразовый — после прохода его нельзя сбросить на начало. Для повторного перебора нужно создать новый итератор.

## ЧТО ТАКОЕ BREAK И CONTINUE И КАК РАБОТАЮТ МЕТКИ (LABELS)?
---
break — полностью прерывает цикл и выходит из него.
continue — пропускает текущую итерацию и переходит к следующей.

```kotlin
for (i in 1..5) {
    if (i == 3) break
    print(i)
}
// 12
```

```kotlin
for (i in 1..5) {
    if (i == 3) continue
    print(i)
}
// 1245
```

Проблема вложенных циклов: break и continue по умолчанию действуют на ближайший цикл. Если нужно прервать внешний цикл из внутреннего — используй метки.

Метка — идентификатор с @ перед циклом:

```kotlin
outer@ for (i in 1..3) {
    for (j in 1..3) {
        if (j == 2) break@outer
        println("$i $j")
    }
}
// 1 1
```

Без метки break прервал бы только внутренний цикл:

```kotlin
for (i in 1..3) {
    for (j in 1..3) {
        if (j == 2) break
        println("$i $j")
    }
}
// 1 1
// 2 1
// 3 1
```

continue с меткой — пропускает итерацию внешнего цикла:

```kotlin
outer@ for (i in 1..3) {
    for (j in 1..3) {
        if (j == 2) continue@outer
        println("$i $j")
    }
}
// 1 1
// 2 1
// 3 1
```

break и continue в when (с Kotlin 1.4): внутри when, вложенного в цикл, break и continue работают без меток — действуют на ближайший цикл.

```kotlin
for (x in listOf(1, 2, 17, 3)) {
    when (x) {
        2 -> continue
        17 -> break
        else -> print("$x ")
    }
}
// 1 3
```

ПЛОХО — метки без необходимости (усложняют чтение):
```kotlin
loop@ for (i in 1..10) {
    if (i > 5) break@loop
}
```

ХОРОШО — метка нужна только когда есть вложенные циклы:
```kotlin
for (i in 1..10) {
    if (i > 5) break
}
```

## КОГДА ИСПОЛЬЗОВАТЬ FOR, А КОГДА WHILE?
---
for — когда известно ЧТО перебираем:
- Коллекция, массив, строка
- Диапазон (конечное количество итераций)
- Любой итерируемый объект

```kotlin
val users = listOf("Алекс", "Боб", "Катя")
for (user in users) println(user)

for (i in 1..10) println(i)
```

while — когда количество итераций неизвестно заранее и зависит от условия:
- Ожидание события
- Чтение до конца потока
- Повторение пока не достигнут результат

```kotlin
var input = readlnOrNull()
while (input != "exit") {
    println("Вы ввели: $input")
    input = readlnOrNull()
}
```

do-while — то же что while, но нужно выполнить действие хотя бы раз:

```kotlin
do {
    val guess = readln().toInt()
    println("Не угадал!")
} while (guess != secret)
```

repeat(n) — когда нужно выполнить блок n раз и не нужен индекс:

```kotlin
repeat(3) {
    println("Повтор")
}
```

Если нужен индекс внутри repeat, он доступен через it:
```kotlin
repeat(3) {
    println("Итерация $it")
}
// Итерация 0
// Итерация 1
// Итерация 2
```

Функциональные альтернативы (не циклы, но заменяют их):
- forEach — перебор без создания нового списка
- map — перебор с преобразованием в новый список
- filter — перебор с отбором по условию

Типичные ошибки выбора (for по индексу вместо for-in, while вместо for) — в вопросе "Антипаттерны циклов".

## АНТИПАТТЕРНЫ ЦИКЛОВ
---

1. Изменение коллекции во время итерации

ПЛОХО — ConcurrentModificationException:
```kotlin
val list = mutableListOf(1, 2, 3, 4, 5)
for (item in list) {
    if (item % 2 == 0) list.remove(item)  // падение в рантайме
}
```

ХОРОШО — через MutableIterator:
```kotlin
val list = mutableListOf(1, 2, 3, 4, 5)
val iter = list.iterator()
while (iter.hasNext()) {
    if (iter.next() % 2 == 0) iter.remove()
}
```

ХОРОШО — создать новую коллекцию:
```kotlin
val result = list.filter { it % 2 != 0 }
```


2. Индексный доступ вместо прямого перебора

ПЛОХО:
```kotlin
for (i in 0 until list.size) {
    println(list[i])
}
```

ХОРОШО:
```kotlin
for (item in list) {
    println(item)
}
```

Если нужен индекс:
```kotlin
for ((i, item) in list.withIndex()) {
    println("$i: $item")
}
```


3. Ручной счётчик в while вместо for

ПЛОХО:
```kotlin
var i = 0
while (i < 10) {
    println(i)
    i++
}
```

ХОРОШО:
```kotlin
for (i in 0..<10) {
    println(i)
}
```


4. Бесконечный цикл без условия выхода

ПЛОХО — зависнет навсегда:
```kotlin
while (true) {
    processItem()
}
```

ХОРОШО — есть выход:
```kotlin
while (true) {
    val item = queue.poll() ?: break
    processItem(item)
}
```


5. Вложенные циклы без необходимости

ПЛОХО — O(n^2) для поиска:
```kotlin
for (user in users) {
    for (order in allOrders) {
        if (order.userId == user.id) {
            println(order)
        }
    }
}
```

ХОРОШО — предварительная группировка, O(n):
```kotlin
val ordersByUser = allOrders.groupBy { it.userId }
for (user in users) {
    ordersByUser[user.id]?.forEach { println(it) }
}
```


6. Пустое тело цикла (логика спрятана в условии)

ПЛОХО — непонятно что происходит:
```kotlin
while (list.removeFirst() != target) {}
```

ХОРОШО — явная логика:
```kotlin
while (true) {
    val item = list.removeFirst()
    if (item == target) break
}
```

## ЧТО ТАКОЕ BIG O И ЗАЧЕМ ОНА НУЖНА?
---
Big O — нотация для описания верхней границы роста времени или памяти алгоритма при увеличении объёма входных данных.

Что измеряет: не точное время в секундах, а СКОРОСТЬ РОСТА. Как быстро растёт количество операций при увеличении данных с n до 2n, 10n, 100n.

Зачем нужна:
- Позволяет сравнивать алгоритмы независимо от железа
- Показывает как алгоритм поведёт себя на больших данных
- Язык общения между разработчиками: "поиск за O(log n)" однозначен

Правила упрощения:
- Константы отбрасываются: O(2n) = O(n)
- Слагаемые складываются, берётся старший: O(n^2 + n) = O(n^2)
- Вложенные операции умножаются: цикл O(n) внутри цикла O(n) = O(n^2)

Пример на циклах:

O(n) — один проход:
```kotlin
for (item in list) {
    println(item)
}
```

O(n^2) — вложенный цикл:
```kotlin
for (i in list) {
    for (j in list) {
        println("$i $j")
    }
}
```

Количество операций растёт не линейно:
n = 10 → 100 операций
n = 100 → 10 000 операций
n = 1000 → 1 000 000 операций

Big O описывает худший случай (worst case). Один и тот же алгоритм может работать по-разному в зависимости от данных:
- Линейный поиск: лучший O(1) (элемент первый), худший O(n) (элемент последний)
- Когда говоришь "сложность O(n)" — имеешь в виду worst case, если не уточнил иначе
!!!
## КАК ОПРЕДЕЛИТЬ СЛОЖНОСТЬ АЛГОРИТМА ПО КОДУ?
---
Простой цикл — O(n):
```kotlin
for (item in list) {
    println(item)
}
```

Вложенные циклы — умножаем:
```kotlin
for (i in list) {           // O(n)
    for (j in list) { ... } // O(n)
}
// Итого: O(n * n) = O(n^2)
```

Последовательные циклы — складываем, берём старший:
```kotlin
for (item in list) { ... } // O(n)
for (item in list) { ... } // O(n)
// Итого: O(n + n) = O(n)
```

Деление пополам на каждом шаге — O(log n):
```kotlin
while (left <= right) {
    val mid = (left + right) / 2
    // идём ЛИБО влево ЛИБО вправо
}
```

Цикл внутри которого вызывается O(log n) операция — O(n log n):
```kotlin
val sortedSet = sortedSetOf<Int>()
for (item in list) {          // O(n)
    sortedSet.add(item)       // O(log n) — вставка в дерево
}
// Итого: O(n log n)
```

Рекурсия с двумя ветвлениями — O(2^n):
```kotlin
fun fib(n: Int): Int {
    if (n <= 1) return n
    return fib(n - 1) + fib(n - 2) // два вызова на каждом уровне
}
```

Пространственная сложность (Space Complexity) — дополнительная память помимо входных данных:
- Цикл сам по себе: O(1) — только переменная-счётчик
- Цикл который собирает результат в новый список: O(n)

```kotlin
val result = mutableListOf<Int>()  // O(n) памяти
for (item in list) {
    if (item > 0) result.add(item)
}
```

Функциональный аналог — та же сложность:
```kotlin
val result = list.filter { it > 0 } // O(n) time, O(n) space
```

Как быстро оценить:
- Видишь один цикл → скорее всего O(n)
- Видишь цикл в цикле → скорее всего O(n^2)
- Видишь деление пополам → скорее всего O(log n)
- Видишь рекурсию с двумя вызовами → скорее всего O(2^n)
!!!
## КАКИЕ ОСНОВНЫЕ КЛАССЫ СЛОЖНОСТИ?
---
От быстрого к медленному:

O(1) — константная:
- Не зависит от размера данных
- Пример: доступ по индексу list[5], получение по ключу map["key"]

```kotlin
val item = list[0]
val value = map["key"]
```

O(log n) — логарифмическая:
- Каждый шаг уменьшает задачу вдвое
- Пример: бинарный поиск

```kotlin
while (left <= right) {
    val mid = (left + right) / 2
    if (arr[mid] == target) return mid
    if (arr[mid] < target) left = mid + 1
    else right = mid - 1
}
```

O(n) — линейная:
- Один проход по всем элементам
- Пример: list.contains(x), sum, поиск максимума

```kotlin
for (item in list) {
    if (item == target) return true
}
```

O(n log n) — линейно-логарифмическая:
- Эффективные сортировки
- Пример: list.sorted() в Kotlin (Timsort)

O(n^2) — квадратичная:
- Вложенный цикл по всем элементам
- Пример: Bubble Sort, перебор всех пар

```kotlin
for (i in list.indices) {
    for (j in list.indices) {
        // обработка пары list[i], list[j]
    }
}
```

O(2^n) — экспоненциальная:
- Удваивается с каждым новым элементом
- Пример: наивная рекурсия Fibonacci, перебор всех подмножеств

O(n!) — факториальная:
- Перебор всех перестановок
- Пример: задача коммивояжёра полным перебором

Наглядно для n = 1000:
O(1) = 1 операция
O(log n) ~ 10 операций
O(n) = 1 000 операций
O(n log n) ~ 10 000 операций
O(n^2) = 1 000 000 операций
O(2^n) = непрактично
O(n!) = непрактично
